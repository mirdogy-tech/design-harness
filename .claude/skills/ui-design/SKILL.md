# UI 설계 & 디자인

와이어프레임, UX 플로우, 비주얼 디자인을 생성하고 Figma와 연동한다.

## 설계 워크플로우

### 1단계: 정보 구조(IA) 설계

디자인 전에 콘텐츠의 구조와 계층을 먼저 정의한다.

```markdown
## 사이트맵
- 홈
  - 기능 A
    - 하위 기능 A-1
    - 하위 기능 A-2
  - 기능 B
  - 설정
    - 프로필
    - 알림
```

**네비게이션 패턴 선택:**
| 패턴 | 적합한 경우 |
|------|-----------|
| 탭 바 (하단) | 모바일, 3~5개 주요 섹션 |
| 사이드 내비게이션 | 데스크톱, 다수 섹션, 깊은 계층 |
| 햄버거 메뉴 | 보조 기능, 공간 절약 필요 |
| 탑 내비게이션 | 데스크톱, 얕은 계층, 브랜드 영역 필요 |

### 2단계: 와이어프레임

#### 텍스트 기반 와이어프레임
Figma 접근이 불가하거나 빠른 아이디어 공유 시 사용.

```
┌─────────────────────────────┐
│  [로고]    [검색...]  [👤]  │  ← 헤더
├─────────────────────────────┤
│                             │
│  ┌───────┐  ┌───────┐      │
│  │ 카드 1 │  │ 카드 2 │     │  ← 메인 콘텐츠
│  │       │  │       │      │
│  └───────┘  └───────┘      │
│                             │
│  ┌───────────────────┐      │
│  │   CTA 버튼         │     │
│  └───────────────────┘      │
│                             │
├─────────────────────────────┤
│  [홈] [탐색] [프로필]       │  ← 하단 탭
└─────────────────────────────┘
```

각 요소에 주석을 달아 상호작용과 콘텐츠를 설명한다:
- **[카드 1]**: 탭 → 상세 페이지 이동. 이미지 + 제목 + 부제 + 메타 정보
- **[CTA 버튼]**: "시작하기" — 온보딩 플로우 진입

#### Figma 기반 와이어프레임
Figma URL이 제공되면 `get_design_context`로 기존 디자인을 분석하고, 디자인 컨텍스트를 기반으로 작업한다.

### 3단계: UX 플로우

#### 태스크 플로우 (단일 경로)
```
[시작] → [화면A: 입력] → [화면B: 확인] → [화면C: 완료]
```

#### 유저 플로우 (의사결정 포함)
```
[시작]
  ↓
[로그인 상태?]
  ├── Yes → [대시보드]
  └── No → [로그인 화면]
              ↓
           [인증 성공?]
              ├── Yes → [대시보드]
              └── No → [에러 표시] → [로그인 화면]
```

#### FigJam 다이어그램
복잡한 플로우는 `generate_diagram` 도구로 FigJam에 시각화한다.

#### 플로우 작성 원칙
- 모든 분기에 **에러/예외 경로**를 포함한다
- 각 화면에 **핵심 액션**과 **탈출 경로**(뒤로, 닫기)를 명시한다
- 비동기 처리(로딩, 타임아웃)를 플로우에 포함한다

### 4단계: 비주얼 디자인

#### 컬러 시스템
```json
{
  "color": {
    "primary": { "50": "#E3F2FD", "500": "#2196F3", "900": "#0D47A1" },
    "secondary": { "50": "#FFF3E0", "500": "#FF9800", "900": "#E65100" },
    "neutral": { "0": "#FFFFFF", "100": "#F5F5F5", "900": "#212121" },
    "semantic": {
      "success": "#4CAF50",
      "warning": "#FFC107",
      "error": "#F44336",
      "info": "#2196F3"
    }
  }
}
```

#### 타이포그래피 스케일
| 레벨 | 크기 | 행간 | 굵기 | 용도 |
|------|------|------|------|------|
| Display | 36px | 44px | Bold | 히어로 제목 |
| H1 | 28px | 36px | Bold | 페이지 제목 |
| H2 | 22px | 28px | SemiBold | 섹션 제목 |
| Body1 | 16px | 24px | Regular | 본문 |
| Body2 | 14px | 20px | Regular | 보조 텍스트 |
| Caption | 12px | 16px | Regular | 캡션, 라벨 |

#### 스페이싱 시스템
4px 기반 스케일: 4, 8, 12, 16, 24, 32, 48, 64, 96

#### 접근성 체크리스트
- [ ] 색상 대비 WCAG AA (일반 텍스트 4.5:1, 큰 텍스트 3:1)
- [ ] 터치 타겟 최소 44×44px
- [ ] 포커스 표시기(Focus indicator) 명확
- [ ] 색상만으로 정보를 전달하지 않음

### 5단계: 컴포넌트 명세

디자인 의도를 ui-builder에게 전달하기 위한 명세서.

```markdown
## 컴포넌트: {이름}

### 상태(States)
- Default / Hover / Active / Focused / Disabled

### Props
| Prop | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| variant | "primary" | "secondary" | "primary" | 스타일 변형 |
| size | "sm" | "md" | "lg" | "md" | 크기 |

### 반응형
| 브레이크포인트 | 변화 |
|--------------|------|
| Mobile (<768px) | 풀 너비, 스택 레이아웃 |
| Tablet (768~1024px) | 2열 그리드 |
| Desktop (>1024px) | 3열 그리드, 사이드바 표시 |

### 인터랙션
- 클릭: {동작}
- 호버: {동작}
- 키보드: {동작}
```

## Figma 연동 참고

| 작업 | 도구 |
|------|------|
| 디자인 읽기·분석 | `get_design_context` (nodeId, fileKey) |
| 스크린샷 | `get_screenshot` |
| 메타데이터 | `get_metadata` |
| FigJam 플로우 | `get_figjam`, `generate_diagram` |
| 디자인 시스템 | `search_design_system`, `get_variable_defs` |

Figma URL 파싱: `figma.com/design/:fileKey/:fileName?node-id=:nodeId` → nodeId의 "-"를 ":"로 변환.
