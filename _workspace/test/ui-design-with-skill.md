# SaaS 대시보드 - 설정 페이지 UI 설계

> 테스트 프롬프트: "SaaS 대시보드의 설정 페이지를 설계해줘. 프로필, 알림, 보안, 결제 섹션이 필요해."
> 스킬: ui-design
> 생성일: 2026-04-05

---

## 1단계: 정보 구조(IA) 설계

### 사이트맵

```
- 대시보드 (홈)
  - 개요
  - 분석
  - ...
  - 설정 ★ (현재 설계 범위)
    - 프로필
      - 기본 정보 (이름, 이메일, 아바타)
      - 계정 정보 (사용자명, 타임존, 언어)
    - 알림
      - 이메일 알림
      - 푸시 알림
      - 인앱 알림
      - 알림 스케줄 (방해금지 시간대)
    - 보안
      - 비밀번호 변경
      - 2단계 인증 (2FA)
      - 활성 세션 관리
      - 로그인 기록
    - 결제
      - 현재 플랜
      - 결제 수단
      - 청구 내역 (인보이스)
      - 플랜 변경 / 업그레이드
```

### 네비게이션 패턴 선택

| 패턴 | 적합한 경우 | 선택 |
|------|-----------|------|
| 탭 바 (하단) | 모바일, 3~5개 주요 섹션 | - |
| **사이드 내비게이션** | **데스크톱, 다수 섹션, 깊은 계층** | **선택** |
| 햄버거 메뉴 | 보조 기능, 공간 절약 필요 | - |
| 탑 내비게이션 | 데스크톱, 얕은 계층, 브랜드 영역 필요 | - |

**결정 근거**: SaaS 대시보드는 데스크톱 우선이며, 설정 페이지는 4개 섹션 + 하위 항목으로 계층이 깊다. 사이드 내비게이션이 섹션 간 이동과 현재 위치 파악에 최적.

**모바일 대응**: 768px 미만에서 사이드 내비게이션은 상단 탭(수평 스크롤) 또는 드롭다운 선택기로 전환.

### 와이어프레임 주석

| 요소 | 상호작용 | 콘텐츠 |
|------|---------|--------|
| **사이드 내비 섹션 항목** | 클릭 시 해당 섹션으로 전환 (SPA, 페이지 리로드 없음) | 아이콘 + 라벨 |
| **아바타 변경** | 클릭 시 파일 업로드 다이얼로그. 최대 5MB, JPG/PNG | 원형 썸네일 |
| **토글 스위치** | 클릭 시 즉시 반영 (auto-save). 실패 시 롤백 + 토스트 | ON/OFF 상태 |
| **비밀번호 변경** | 클릭 시 모달 오픈. 현재 비밀번호 + 새 비밀번호 + 확인 | 마지막 변경일 표시 |
| **2FA 설정하기** | 클릭 시 스텝 위자드 (QR코드 스캔 -> 코드 입력 -> 백업 코드) | 활성/비활성 뱃지 |
| **세션 종료** | 클릭 시 확인 다이얼로그 -> 즉시 종료 | 디바이스 정보 |
| **플랜 변경** | 클릭 시 플랜 비교 페이지/모달 | 현재 플랜 하이라이트 |
| **변경사항 저장** | 유효성 검사 후 저장. 성공 시 토스트 알림 | Primary 버튼 |
| **취소** | 변경사항 되돌리기. 미저장 변경 있으면 확인 다이얼로그 | Ghost 버튼 |

## 3단계: UX 플로우

### 3-1. 유저 플로우 - 프로필 수정

```
[설정 진입]
  ↓
[프로필 섹션 표시 (기본)]
  ↓
[사용자가 필드 수정]
  ↓
[변경 감지 → "변경사항 저장" 버튼 활성화]
  ↓
[저장 클릭]
  ↓
[유효성 검사]
  ├── 성공 → [API 호출 (로딩 스피너)]
  │            ├── 200 OK → [성공 토스트 "프로필이 업데이트되었습니다"] → [버튼 비활성화]
  │            ├── 409 Conflict → [인라인 에러 "이미 사용 중인 이메일입니다"]
  │            └── 5xx / 타임아웃 → [에러 토스트 "저장 실패. 다시 시도해주세요."] → [버튼 유지]
  └── 실패 → [인라인 에러 표시 (해당 필드 하단)]
              예: "이름은 2자 이상 입력해주세요"
```

### 3-2. 유저 플로우 - 알림 토글 변경

```
[알림 섹션 진입]
  ↓
[토글 클릭]
  ↓
[낙관적 업데이트 (즉시 UI 반영)]
  ↓
[API 호출]
  ├── 성공 → [상태 유지]
  └── 실패 → [토글 롤백] → [에러 토스트 "알림 설정 변경에 실패했습니다"]
```

### 3-3. 유저 플로우 - 비밀번호 변경

```
[보안 섹션 → "비밀번호 변경" 클릭]
  ↓
[모달 오픈]
  ↓
[현재 비밀번호 입력]
  ↓
[새 비밀번호 입력]
  ↓
[비밀번호 확인 입력]
  ↓
[실시간 강도 표시 (약함/보통/강함)]
  ↓
["변경" 클릭]
  ↓
[유효성 검사]
  ├── 새 비밀번호 != 확인 → [인라인 에러 "비밀번호가 일치하지 않습니다"]
  ├── 강도 미달 → [인라인 에러 "8자 이상, 대소문자+숫자+특수문자 포함"]
  └── 통과 → [API 호출]
              ├── 200 OK → [성공 토스트] → [모달 닫기] → [마지막 변경일 갱신]
              ├── 401 → [인라인 에러 "현재 비밀번호가 올바르지 않습니다"]
              └── 5xx → [에러 토스트 "변경 실패. 다시 시도해주세요."]
```

### 3-4. 유저 플로우 - 2FA 설정

```
[보안 섹션 → "2FA 설정하기" 클릭]
  ↓
[스텝 1: QR 코드 표시]
  ↓
[사용자: 인증 앱으로 스캔]
  ↓
["다음" 클릭]
  ↓
[스텝 2: 인증 코드 입력 (6자리)]
  ↓
["확인" 클릭]
  ↓
[API 검증]
  ├── 성공 → [스텝 3: 백업 코드 10개 표시]
  │            ↓
  │          ["코드를 안전하게 저장했습니다" 체크박스]
  │            ↓
  │          ["완료" 클릭] → [2FA 활성 뱃지 표시]
  ├── 코드 불일치 → [인라인 에러 "잘못된 인증 코드"] → [재입력 허용 (최대 5회)]
  └── 최대 시도 초과 → [에러 표시 "잠시 후 다시 시도해주세요"] → [모달 닫기]

탈출 경로:
  - 모든 스텝에서 [X 닫기] 가능 → 확인 다이얼로그 "설정을 취소하시겠습니까?"
  - 스텝 2에서 [← 이전] → 스텝 1로 복귀
```

### 3-5. 유저 플로우 - 플랜 변경

```
[결제 섹션 → "플랜 변경" 클릭]
  ↓
[플랜 비교 모달/페이지]
  ↓
[플랜 선택]
  ├── 업그레이드 → [결제 확인 화면 (차액 표시)]
  │                 ↓
  │               ["결제하기" 클릭]
  │                 ↓
  │               [결제 처리 (로딩)]
```

### 3-6. 에러 플로우 요약

| 에러 유형 | 처리 방법 | UI 패턴 |
|-----------|----------|---------|
| 유효성 검사 실패 | 해당 필드 하단에 인라인 에러 메시지 | 빨간 테두리 + 에러 텍스트 |
| API 4xx (클라이언트 에러) | 구체적 에러 메시지를 인라인으로 표시 | 인라인 에러 또는 배너 |
| API 5xx (서버 에러) | 일반 에러 토스트 + 재시도 유도 | 토스트 알림 |
| 네트워크 타임아웃 | "연결 상태를 확인해주세요" 토스트 | 토스트 알림 |
| 세션 만료 (401) | 로그인 페이지로 리다이렉트 | 전체 화면 |
| 권한 없음 (403) | "이 작업을 수행할 권한이 없습니다" | 인라인 배너 |
| 미저장 변경 + 이탈 | "저장하지 않은 변경사항이 있습니다" 확인 다이얼로그 | 모달 다이얼로그 |

## ui-builder 전달 요약

위 컴포넌트 명세를 기반으로 ui-builder가 구현해야 할 핵심 사항:

1. **레이아웃**: `SettingsLayout` (사이드 내비 + 콘텐츠) 반응형 구현
2. **내비게이션**: `SettingsSideNav` - URL hash 기반 섹션 전환
3. **폼**: `FormField` 기반 프로필 편집 폼, 유효성 검사, 인라인 에러
4. **토글**: `ToggleRow` - 낙관적 업데이트 + 롤백 패턴
5. **보안**: 비밀번호 변경 모달, 2FA 스텝 위자드, 세션 관리
6. **결제**: 플랜 카드, 결제 수단 CRUD, 인보이스 테이블
7. **공통**: `ActionButton` 전 variant, 토스트 알림 시스템, 확인 다이얼로그
8. **디자인 토큰**: 위 컬러/타이포/스페이싱을 CSS 변수 또는 theme 객체로 구성
