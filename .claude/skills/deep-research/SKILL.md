# 딥 리서치

다중 소스(웹, 학술, 커뮤니티)에서 정보를 수집하고, 교차 검증하여 신뢰도 높은 종합 보고서를 작성한다.

## 리서치 워크플로우

### 1단계: 리서치 프레이밍
1. 핵심 질문 정의 — 답해야 할 구체적 질문 목록 작성
2. 범위 설정 — 시간 범위, 지역, 도메인 한정
3. 소스 전략 수립 — 어떤 유형의 소스에서 무엇을 찾을지 계획

### 2단계: 다중 소스 수집

#### 웹 리서치 (WebSearch + WebFetch)
- **1차 검색**: 핵심 키워드 3~5개 조합으로 WebSearch 실행
- **2차 검색**: 1차 결과에서 발견된 전문 용어·인물·기업으로 추가 검색
- **심화 수집**: 유망한 URL을 WebFetch로 상세 내용 추출
- 검색 쿼리를 영어/한국어 양쪽으로 실행하여 언어별 정보 격차 보완

#### 학술 리서치
- 키워드 기반 학술 검색 (Google Scholar, arXiv, ACM DL 등)
- 핵심 논문의 참고문헌 체이닝 (snowball search)
- 수집 대상: 제목, 저자, 연도, 초록, 핵심 발견, 방법론
- HCI, 인지심리학, 정보 과학 분야 우선

#### 커뮤니티 리서치
- 대상 플랫폼: Reddit, Twitter/X, Hacker News, Product Hunt, Designer News, 디자인 커뮤니티
- 수집 방법: 키워드 검색 → 관련 스레드/포스트 수집 → 감성 분류
- 분류 기준:
  - **감성**: 긍정 / 부정 / 중립
  - **유형**: 기능 요청 / 버그 보고 / 칭찬 / 비교 / 질문
  - **빈도**: 동일 의견이 몇 번 반복되는지

### 3단계: 교차 검증

교차 검증은 딥 리서치의 핵심이다. 단일 소스의 주장을 사실로 채택하지 않는다.

#### 검증 매트릭스
| 주장 | 웹 소스 | 학술 소스 | 커뮤니티 | 일치도 | 판정 |
|------|--------|----------|---------|--------|------|
| X | ✓ 소스A | ✓ 논문B | ✓ Reddit | 3/3 | **확인됨** |
| Y | ✓ 소스C | ✗ 해당 없음 | ✓ Twitter | 2/2 | **가능성 높음** |
| Z | ✓ 소스D | ✗ 반박 논문E | ✗ 반대 의견 | 1/3 | **논쟁적** |

#### 신뢰도 등급
- **높음**: 3개 이상 독립 소스에서 확인, 학술 근거 존재
- **중간**: 2개 소스에서 확인, 또는 신뢰할 만한 단일 소스 (공식 문서, 주요 연구)
- **낮음**: 단일 소스, 또는 소스 간 상충

#### 상충 정보 처리
상충하는 정보를 발견하면 삭제하지 않는다. 다음 형식으로 병기한다:
```markdown
> **상충 발견**: {주장 A} vs {주장 B}
> - A 근거: {소스, 논거}
> - B 근거: {소스, 논거}  
> - 판단: {어느 쪽이 더 신뢰할 만한지, 또는 판단 보류 이유}
```

## 검색 전략 팁

- **키워드 확장**: 동의어, 상위/하위 개념, 영어/한국어 병행
