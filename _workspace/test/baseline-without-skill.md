## Prompt 1: UX Research -- 장바구니-결제 전환율 분석 및 A/B 테스트 설계

### 1. 현황 진단

장바구니-결제 전환율 30%는 업계 평균(약 35~45%, Baymard Institute 기준)보다 낮은 수치다. 이는 장바구니에 담은 사용자 10명 중 7명이 결제를 완료하지 않고 이탈한다는 뜻이다.

### 2. 주요 이탈 지점 분석

퍼널을 세분화하면 다음 단계에서 이탈이 집중될 가능성이 높다.

| 단계 | 예상 이탈 원인 | 확인 방법 |
|------|--------------|----------|
| 장바구니 페이지 | 예상치 못한 배송비/추가 비용 노출, 복잡한 UI | GA4 이벤트 퍼널, 히트맵(Hotjar 등) |
| 회원가입/로그인 | 강제 회원가입 요구, 소셜 로그인 미지원 | 퍼널 단계별 이탈률 비교 |
| 배송 정보 입력 | 폼 필드 과다, 주소 자동완성 미지원 | 폼 분석(form analytics), 세션 리플레이 |
| 결제 수단 선택 | 선호 결제 수단 부재, 보안 불신 | 결제 수단별 전환율 비교 |
| 결제 확인(최종) | 최종 금액 변동, 느린 로딩, 결제 오류 | 에러 로그, 서버 응답 시간 모니터링 |

### 3. 데이터 수집 전략

**정량 분석:**
- GA4 또는 Amplitude로 단계별 퍼널 이벤트 추적 (cart_view -> checkout_start -> shipping_info -> payment_info -> purchase)
- 디바이스별, 유입 채널별, 신규/재방문 사용자별 세분화
- 평균 체류 시간 및 스크롤 깊이 측정

**정성 분석:**
- 이탈 사용자 대상 exit-intent 설문 (1문항: "결제를 완료하지 않은 이유는?")
- 5~8명 대상 모더레이트 사용성 테스트 (Think-aloud)
- 세션 리플레이 50~100건 분석하여 rage click, u-turn 패턴 식별

### 4. A/B 테스트 설계

#### 테스트 A: 게스트 체크아웃 도입

- **가설**: 강제 회원가입을 제거하고 게스트 체크아웃을 허용하면 장바구니-결제 전환율이 15% 이상 증가할 것이다.
- **대조군(Control)**: 현행 강제 회원가입 플로우
- **실험군(Variant)**: 게스트 체크아웃 옵션 추가 (이메일만 입력)
- **주요 지표(Primary Metric)**: 장바구니-결제 완료 전환율
- **보조 지표**: 평균 주문 금액(AOV), 결제 완료까지 소요 시간, 재구매율
- **트래픽 배분**: 50/50
- **최소 샘플 크기**: MDE 5%, 검정력 80%, 유의수준 5% 기준으로 약 그룹당 1,500~2,000 세션
- **테스트 기간**: 최소 2주 (요일 효과 상쇄)

#### 테스트 B: 배송비 사전 고지

- **가설**: 장바구니 페이지에서 예상 배송비를 미리 표시하면 결제 단계 이탈률이 10% 이상 감소할 것이다.
- **대조군**: 결제 단계에서만 배송비 노출
- **실험군**: 장바구니 페이지 상단에 예상 배송비 표시 + 무료배송까지 남은 금액 프로그레스 바
- **주요 지표**: 장바구니 -> 결제 정보 입력 단계 전환율
- **보조 지표**: 장바구니 이탈률, AOV 변화
- **트래픽 배분**: 50/50
- **테스트 기간**: 2주

#### 테스트 C: 결제 폼 간소화

- **가설**: 결제 폼 필드를 12개에서 6개로 줄이면(주소 자동완성, 불필요 필드 제거) 전환율이 20% 이상 증가할 것이다.
- **대조군**: 현행 12필드 폼
- **실험군**: 6필드 간소화 폼 (이름, 전화번호, 주소 자동완성, 결제수단)
- **주요 지표**: 배송정보 입력 -> 결제 완료 전환율
- **테스트 기간**: 2주

### 5. 우선순위 및 실행 로드맵

1. **1주차**: 퍼널 이벤트 계측 점검 및 데이터 수집 시작
2. **2~3주차**: 정량 데이터 분석으로 최대 이탈 지점 특정
3. **3~4주차**: 최대 이탈 지점에 해당하는 A/B 테스트 1개 우선 실행
4. **6주차**: 결과 분석 및 승자 variant 배포, 다음 테스트 착수

## Prompt 2: Deep Research -- 2024~2025 모바일 앱 온보딩 UX 트렌드

### 1. 개요

모바일 앱 온보딩은 사용자가 앱을 처음 실행한 후 핵심 가치를 경험하기까지의 여정이다. 2024~2025년에는 AI 개인화, 점진적 공개, 인터랙티브 튜토리얼 등이 주요 트렌드로 부상했다.

### 2. 주요 트렌드 분석

#### 트렌드 1: AI 기반 적응형 온보딩

- **설명**: 사용자의 행동 데이터, 디바이스 컨텍스트, 유입 경로 등을 기반으로 온보딩 플로우를 실시간으로 개인화한다.
- **근거**: Appcues 2024 Product Adoption Report에서 개인화된 온보딩이 활성화율을 평균 28% 향상시켰다고 보고. 학술적으로도 Sundar & Marathe(2010)의 MAIN 모델에서 개인화가 사용자 경험에 미치는 긍정적 영향이 지속적으로 확인됨.
- **사례**: Spotify의 장르/아티스트 선택 플로우, Duolingo의 레벨 테스트 기반 커리큘럼 매칭, TikTok의 콘텐츠 선호도 피드백 루프.

#### 트렌드 2: 점진적 공개 (Progressive Disclosure)

- **설명**: 한 번에 모든 기능을 설명하지 않고, 사용자가 필요한 시점에 관련 기능을 점진적으로 소개한다.
- **근거**: Nielsen Norman Group(2024)은 정보 과부하가 온보딩 이탈의 1위 원인임을 지적. Slack, Notion 등이 이 패턴으로 전환 후 Day-7 리텐션이 개선되었다는 업계 보고가 있음.
- **사례**: Notion의 빈 상태(empty state) 활용 -- 빈 페이지에서 자연스럽게 기능 발견을 유도. Figma의 컨텍스트 툴팁.

#### 트렌드 3: 인터랙티브 & 게이미피케이션 온보딩

- **설명**: 수동적인 슬라이드 튜토리얼 대신, 사용자가 직접 핵심 작업을 수행하며 학습하는 방식.
- **근거**: 학습 이론(Learning by Doing, Dewey)에 기반. Chameleon의 2024 SaaS Onboarding Benchmark에서 인터랙티브 온보딩이 정적 온보딩 대비 완료율 2.5배 높음.
- **사례**: Duolingo의 첫 레슨 즉시 시작, Canva의 첫 디자인 만들기 유도, Revolut의 첫 송금 가이드.

#### 트렌드 4: 권한 요청 최적화

- **설명**: 알림, 위치, 카메라 등 권한을 앱 시작 시 한꺼번에 요청하지 않고, 해당 기능 사용 직전에 맥락과 함께 요청한다.
- **근거**: Google의 Android 디자인 가이드라인(2024 업데이트)과 Apple의 HIG 모두 컨텍스트 기반 권한 요청을 권장. pre-prompt 화면(사전 설명 화면)을 추가하면 수락률이 약 30% 증가한다는 데이터가 다수 존재(OneSignal, CleverTap 보고).

#### 트렌드 5: 스킵 가능하고 복귀 가능한 온보딩

- **설명**: 온보딩을 강제하지 않고, 스킵 옵션과 나중에 다시 볼 수 있는 진입점을 제공한다.
- **근거**: UX 커뮤니티(Reddit r/userexperience, Designer News)에서 "강제 온보딩 슬라이드"에 대한 부정적 피드백이 지속적으로 관찰됨. Leanplum(2024)은 스킵 가능한 온보딩이 앱 삭제율을 18% 낮춘다고 보고.

#### 트렌드 6: 가치 우선 (Value-First) 온보딩

- **설명**: 계정 생성이나 프로필 설정 전에 앱의 핵심 가치를 먼저 체험하게 한다.
- **근거**: Nir Eyal의 Hook Model에서 trigger -> action -> reward 사이클의 첫 reward를 빠르게 전달하는 것이 핵심. Product-Led Growth(PLG) 전략의 기본 원칙.
- **사례**: Calm의 첫 명상 세션 즉시 제공, Pinterest의 로그인 없이 피드 탐색 허용.

### 3. 커뮤니티 반응 종합

| 출처 | 긍정 반응 | 부정 반응 |
|------|----------|----------|
| Reddit r/userexperience | 점진적 공개, 가치 우선 접근에 호평 | 과도한 게이미피케이션, 강제 튜토리얼에 대한 피로감 |
| Designer News / Hacker News | AI 개인화에 대한 기대감 | 프라이버시 우려, "dark pattern" 경계 |
| Product Hunt 커뮤니티 | 인터랙티브 온보딩 도구(Appcues, Chameleon) 관심 증가 | 소규모 팀에게는 구현 비용 부담 |

### 4. 교차 검증 요약

- **학술 + 업계 보고서 일치**: 개인화와 점진적 공개가 사용자 경험에 긍정적이라는 점은 학술 연구와 업계 벤치마크 모두에서 확인됨.
- **업계 보고서 + 커뮤니티 불일치**: 게이미피케이션의 경우 업계 보고서는 긍정적이나, 커뮤니티에서는 "과도한 게이미피케이션은 역효과"라는 의견이 상당수.
- **공통 합의**: 온보딩은 짧아야 하고, 핵심 가치를 빠르게 전달해야 하며, 사용자에게 통제권을 줘야 한다.

### 5. 권장 사항

1. 3단계 이내의 핵심 가치 체험형 온보딩 설계
2. AI 기반 개인화는 프라이버시 투명성과 병행
3. 권한 요청은 반드시 컨텍스트 기반으로 분리
4. A/B 테스트로 온보딩 단계 수 및 방식 최적화
5. 온보딩 완료율, Day-1/Day-7 리텐션, Time-to-Value를 핵심 KPI로 추적

## Prompt 3: UI Design -- SaaS 대시보드 설정 페이지

### 1. 설계 원칙

- **일관성**: 대시보드 전체 디자인 시스템과 동일한 컴포넌트 사용
- **스캔 가능성**: 섹션 간 명확한 시각적 구분, 레이블 명확화
- **점진적 복잡도**: 자주 사용하는 설정을 상단에, 고급 설정은 하단에 배치
- **즉각적 피드백**: 저장 성공/실패, 변경 사항 감지 시 즉시 알림

### 2. 정보 구조 (IA)

```
Settings
├── Profile (프로필)
│   ├── 아바타
│   ├── 이름
│   ├── 이메일
│   ├── 직책 / 역할
│   ├── 타임존
│   └── 언어
├── Notifications (알림)
│   ├── 이메일 알림
│   │   ├── 마케팅 / 뉴스레터
│   │   ├── 제품 업데이트
│   │   └── 활동 요약 (일간/주간)
│   ├── 푸시 알림
│   │   ├── 멘션 / 댓글
│   │   ├── 작업 할당
│   │   └── 시스템 알림
│   └── 알림 스케줄 (방해금지 시간대)
├── Security (보안)
│   ├── 비밀번호 변경
│   ├── 2단계 인증 (2FA)
│   │   ├── 인증 앱 (TOTP)
│   │   ├── SMS
│   │   └── 백업 코드
│   ├── 활성 세션 관리
│   ├── 로그인 기록
│   └── API 키 관리
└── Billing (결제)
    ├── 현재 플랜
    ├── 사용량 / 한도
    ├── 결제 수단
    ├── 청구서 기록
    └── 플랜 변경 / 취소
```

### 3. 레이아웃 설계

```
+------------------------------------------------------------------+
| Settings                                                          |
+------------------------------------------------------------------+
|                                                                    |
|  [Profile]  [Notifications]  [Security]  [Billing]    <- 탭 네비  |
|                                                                    |
+------------------------------------------------------------------+
|                                                                    |
|  Profile                                                          |
|  ─────────────────────────────────────────────                    |
|                                                                    |
|  +--------+                                                       |
|  | Avatar |  이름: ___________________                            |
|  | (edit) |  이메일: _________________  [Verified]                |
|  +--------+  직책: ___________________                            |
|              타임존: [드롭다운 ▼]                                   |
|              언어:   [드롭다운 ▼]                                   |
|                                                                    |
|              [변경사항 저장]  [취소]                                 |
|                                                                    |
+------------------------------------------------------------------+
```

**네비게이션 패턴**: 화면 너비 768px 이상에서는 좌측 사이드 네비게이션 또는 상단 탭. 모바일에서는 아코디언 또는 풀스크린 네비게이션으로 전환.

### 4. 섹션별 상세 설계

#### 4.1 Profile (프로필)

- **아바타**: 원형 이미지, 호버 시 "Edit" 오버레이, 최대 5MB / JPG, PNG 지원
- **이름/이메일**: 텍스트 인풋, 이메일 변경 시 인증 메일 발송 플로우
- **타임존/언어**: 검색 가능한 드롭다운 (Combobox)
- **저장**: 변경 감지 시 하단 플로팅 바에 "저장" / "취소" 버튼 표시

#### 4.2 Notifications (알림)

- **토글 기반 UI**: 각 알림 항목을 on/off 토글로 제어
- **그룹핑**: "이메일 알림", "푸시 알림"으로 구분된 카드
- **마스터 토글**: 각 그룹 상단에 전체 on/off 토글
- **방해금지**: 시간대 선택기 (e.g., 22:00 ~ 08:00)
- 변경 시 자동 저장 (auto-save) + 토스트 알림 "설정이 저장되었습니다"

```
+------------------------------------------+
| Email Notifications                       |
| [Master Toggle: ON]                       |
|                                           |
|   Marketing & Newsletter     [Toggle ON]  |
|   Product Updates            [Toggle ON]  |
|   Activity Digest            [Weekly ▼]   |
|                                           |
+------------------------------------------+
| Push Notifications                        |
| [Master Toggle: ON]                       |
|                                           |
|   Mentions & Comments        [Toggle ON]  |
|   Task Assignments           [Toggle ON]  |
|   System Alerts              [Toggle OFF] |
|                                           |
+------------------------------------------+
| Do Not Disturb                            |
|   [22:00] to [08:00]        [Toggle OFF]  |
+------------------------------------------+
```

#### 4.3 Security (보안)

- **비밀번호 변경**: 현재 비밀번호 + 새 비밀번호 + 확인 필드. 비밀번호 강도 표시기.
- **2FA**: 상태 배지 (Enabled/Disabled). 활성화 시 QR코드 + 수동 입력 키 제공. 백업 코드 다운로드.
- **활성 세션**: 테이블 (디바이스, IP, 위치, 마지막 활동, "로그아웃" 버튼)

### 5. 인터랙션 패턴

| 패턴 | 설명 |
|------|------|
| Auto-save vs Manual save | 알림: 자동 저장 + 토스트. 프로필/보안/결제: 수동 저장 + 확인 |
| Unsaved changes guard | 프로필 수정 후 다른 탭 이동 시 "저장하지 않은 변경사항이 있습니다" 모달 |
| Destructive actions | 계정 삭제, 세션 해제, API 키 삭제 시 확인 모달 + 텍스트 입력 확인 |
| Loading states | 각 섹션 진입 시 스켈레톤 UI 표시 |
| Error handling | 인라인 에러 메시지 (필드 하단 빨간 텍스트) + 토스트 (서버 에러) |

### 6. 접근성 고려사항

- 모든 토글/버튼에 aria-label 제공
- 키보드 네비게이션: Tab으로 섹션 간 이동, Enter로 토글 전환
- 색상 대비 WCAG AA 이상 충족
- 스크린 리더: 설정 변경 시 aria-live 영역으로 상태 변경 알림

### 7. 반응형 브레이크포인트

| 브레이크포인트 | 레이아웃 |
|--------------|---------|
| >= 1024px | 좌측 사이드 네비 + 우측 콘텐츠 영역 |
| 768px ~ 1023px | 상단 탭 네비 + 전체 너비 콘텐츠 |
| < 768px | 설정 목록 -> 개별 섹션 풀스크린 전환 (drill-down) |
